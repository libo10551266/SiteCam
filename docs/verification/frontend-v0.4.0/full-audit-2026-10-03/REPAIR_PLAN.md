## R1：资料保留、遮盖与拍摄归属

### R1a：录制中断与保存接管（AND-CM01、AND-CM02）

**最小改动**：Android `CameraViewModel` 根据 Finalize 错误种类与输出可读性决定保留有效片段或清除无有效数据；生命周期主动停止与错误兜底共同覆盖 Home/锁屏。继续使用原冻结工程、时间、水印和保存目标，不把所有错误一律当成功。

将录制原片、烧录临时输出、最终文件和数据库索引的所有权写清：物理复制不能提前消费调用者唯一输入；仅当可靠文件和对应索引已接管后才能删除最后一份原片。文件写流或 Room 提交失败时，保留可播放源及恢复所需快照，让既有重试/再次保存流程能找到；只有保留完成后才可提示“已保留原片”。保持正常成功后的及时清理，不增加无目的备份。

**影响位置**：Android `feature/camera/CameraViewModel.kt` 的 Finalize 与保存分支，`core/media/MediaStoreManager.kt` 的调用者输入所有权，必要的现有恢复入口。原有工程预约、STARTING 停止请求和迟到录制事件 token 继续保留。

**验收关卡 GR1a**：一台设备顺序完成“录制数秒→Home→返回”“锁屏→返回”、无有效帧、编码失败；分别注入写流失败与 Room 插入失败。有效素材至少有一份可播放源和正确冻结归属，恢复后可再次保存且不重复建记录；无效空文件不被伪装成功。测试和运行分别记录是否拿到实际错误码，不由画面推断 CameraX 枚举。

### R1b：使脱敏遮盖与底图无关（AND-CM03）

**最小改动**：Android 预览与成品使用完全不透明的现有棋盘块，保持几何、配方、撤销/重做和原图编辑语义。无需新增安全功能或整图副本。

**影响位置**：`PhotoAnnotationViewModel.kt` 成品 painter 与 `PhotoAnnotationScreen.kt` 对应预览颜色。

**验收关卡 GR1b**：黑白细字/棋盘底图上作短笔、边缘与对角笔划，单次覆盖块内部输出不随底图改变；JPEG 成品的遮盖范围与预览一致。只针对该结果检查，不开展额外安全扫描。

### R1c：照片回调固定请求与会话归属（HCM-01）

**最小改动**：HarmonyOS 对成功、失败、capture 拒绝、超时及关闭建立同一请求/会话代次，完成一次后失效；回调不访问可能属于下一次请求的共享 resolver。API 12 的 `Photo` 本身没有 capture ID，因此不能只在晚到回调入口读取“当前 token”。没有可靠输出关联时，超时先失效并释放/重建原输出，再接受下一拍；已进入异步 JPEG 读取的旧闭包仍按旧会话检查并释放自己的资源。

**影响位置**：`CameraService.ets:349、413–414、539`；页面继续使用已冻结快照，不改水印内容或工程语义。

**验收关卡 GR1c**：A 超时→B 开始→A 成功或错误迟到，以及 A 回调读图中关闭/重开；B 不获得 A 字节、不被 A 错误拒绝。两场景/两套水印可区分，正常连续拍摄、闪光和快门音回调不回退。

### R1d：删除取消、完整成员与文件/索引收尾（AND-DATA-01/02/03、HAR-DATA-03）

**Android 取消收尾**：删除索引进入不可随页面遗弃的阶段后，将必要文件操作和补偿放进能完成该临界收尾的作用域；按媒体 ID 和阶段判断完成/恢复。退出相册不应让恢复代码继续运行在已取消的上下文。仅禁用返回或已有全局互斥锁均不能代替取消处理；不用整个应用范围的长期不可取消任务掩盖问题。

**Android 工程删除**：删除用查询返回该工程全部记录，包含 `isUnavailable` 资料；逐一协调原件、独立标注和问题，原件确实不存在可沿用现有清索引分支。工程成员枚举、逐项删除与最终删工程同相册移动共享一致操作边界，提交时检查成员归属；避免在非重入锁里再次调用自动取同锁的方法。不能只给双栏按钮置灰而保留数据竞争。

**HarmonyOS 删除**：详情、批量和工程删除复用一处阶段协调，使文件删除部分成功、数据库失败或重启后可按已完成阶段收尾；展示与重试状态须反映真实文件存在性。不能只交换两句调用顺序就宣称文件系统和数据库已原子提交，也不把系统相册副本误纳入私有文件删除。

**影响位置**：Android `MediaDeletionCoordinator`、`MediaStoreManager`、`MediaItemDao`、`ProjectViewModel`、`GalleryViewModel` 的已有协调入口；HarmonyOS `Index.ets` 的删除调用、`MediaService/ImageProcessor` 的文件删除和 `Store` 的事务交界。先约定必要的阶段与归属，再决定最小数据表示，不进行无关迁移或全目录扫描。

**验收关卡 GR1d**：分别在标注索引删除后、媒体索引删除后、物理删除返回前取消；结果须是完整删除或保持真实可重试记录。带标注照片进入系统回收站后删除工程，独立标注文件被处理；A→B 移出和 B→A 移入覆盖枚举前后及逐项删除之间，成功移入 B 的资料不被 A 旧任务删掉。鸿蒙分别注入第二次 unlink、媒体事务、工程最后事务失败，界面/索引/文件状态一致且能继续收尾。只用独立样本。

关卡 GR2a：已有标注时令下一次读图失败，恢复后核对画面、配方、撤销/重做和成品一致；与 B3 裁剪基准/取消手势一并回归，不重新定义编辑工具。

### R2c：视频取消和工作进展（HCM-02、HCM-04）

在 ArkTS 服务保存作业代次与取消状态，每个异步预处理返回后、原生调用前、输出检查后及提交前验证。原生取消关联本次作业，下一初始化不能抹掉本次已有取消；跨过明确提交点后按既定完成结果处理，不能承诺已完成提交可回滚。

把 UI 95% 封顶与工作活动计时分开，用实际解码/编码帧或阶段进展刷新单调时钟；保留真实停滞超时。失败/取消清理未提交输出且保留原片，不延长固定超时掩盖问题。

关卡 GR2c：逐个阻塞媒体读取、视频探测、水印读像素、输出校验，取消后放行；前半段不启动后续 native，提交前取消不写 READY，下一正常任务不受旧取消影响。末 5% 持续推进超过 45 秒应完成，完全无进展仍超时。顺序用单台设备或可控任务检查，不能为长视频并开多模拟器。

### R2d：视频色彩与帧率候选（HCM-05、HCM-C01）

先获取实际源轨道与解码输出的范围/矩阵，并用灰阶和色块比较无水印区域；若覆盖实际支持的非 BT.601 limited 输入，选择匹配的转换及输出元数据。保持现有 SDR 支持范围，不扩展 HDR 业务。API 10 的基础颜色键可用于 API 12 基线，不能无条件引入更高 API。

HCM-C01 先读目标设备真实 profile：只有确认当前选择导致相机/录制器帧率不一致并影响录制，才按合法范围选档；不将尚未证实设备存在的 60 fps-only 档位写成已发生故障。

关卡 GR2d：源/成品无叠加区域的黑白层次和色块、实际录制帧率/时长/声音，四方向输出尺寸与播放方向。既有 `VideoOutputChecks` 的 320×240 首中尾水印抽帧保留，但不替代颜色、连续播放与声音验证。

### R2e：设置恢复与跨入口写入顺序（HAR-DATA-01、HAR-DATA-02）

`Store.open` 恢复 `cameraControlStyle`，仅接受现有 NORMAL/BLUR；旧记录无字段沿用 NORMAL。成功写入后重启仍丢失的读取问题与 HAR-S15 的写入失败处理分别修复。

统一设置提交顺序和字段归属：快捷水印队列只提交自己拥有的水印状态，不能在模板数据库等待后将旧 `currentProject`、画质、相册副本或声音写回。保留水印任务之间的 FIFO，但所有设置入口必须遵守一致的最新值规则；单纯等待 UI Promise 或重排一处回调不足以防交错覆盖。

**验收关卡 GR2e**：NORMAL、BLUR、旧版缺字段三组保存→关闭→重开；阻塞一次水印模板更新，随后成功切工程 A→B 或修改画质，再放行旧队列并重开，最新工程与画质不回退。B4 接此结果处理 UI draft/保存失败和即时预览，避免重复建设两套设置状态。

导出服务的数据侧本轮没有新增独立确认问题；进度/取消仍归 HAR-S07，视频 CSV 字段仍归 HCM-03。定位权限回收已有代次/归属保护，不新增没有具体证据的“旧地址必然回来”修复项。
