# Android 管理页与折叠几何修复

日期：2026-10-04。对应 B1 的窗口容量、二维折痕与宽窄衔接；本分工未执行构建、测试或启动设备，统一验证由主审负责。

- `ScreenEnvironment.kt` 沿用主审的当前窗口信息及完整 folds 列表，新增 `localFolds` 与 `AdaptivePaneLayout`。页面先消费四边 safeDrawing，再把全部分隔、遮挡和半展开折痕转入局部坐标；Dialog 与 Activity 窗口原点不同时扣除其实际差值，不重复减显示器上的窗口位置。
- `ScreenProfile.kt` 新增纯函数可用矩形划分和双栏容量计算。840dp 仅为初始参考，两栏最小文字容量随字号增加；折痕间的空间单独判断。空间不足时在最大完整区域单栏显示。跨折痕的文字和交互内容由各自内容区约束。
- `AppNavHost.kt` 相册、`ProjectListScreen.kt` 工程与 `SettingsScreen.kt` 采用同一规则，不再依赖整窗 600dp/840dp 或设备标签。相册及工程浏览槽位固定，宽窄变化保留当前媒体/工程；工程卡片只浏览，独立“去拍摄”继续走原选择逻辑。
- `CameraGeometry.kt` 增加可选完整 `folds`、`fontScale`，保留旧参数和 `hover` 语义。多条折痕共同划区；悬停预览及操作区上下分置；近平方局部窗口保留右栏。预览继续严格 4:3/3:4。相机页面参数接入和控件尺寸由主审负责。
- `WatermarkStylePicker.kt` 使用弹窗实际约束，单个安全区域容纳标题、滚动样式和确认按钮。样式列数跟随宽度/字号，标签保持 14sp；选择及滚动状态沿用同一份状态。

`ScreenAdaptationTest.kt` 新增结果断言：840dp 与字号容量、多条二维折痕/零宽分隔、局部坐标偏移、近平方右栏、相机预览/操作区均不与任一折痕相交。尚待统一执行，不能替代真实折叠姿态、Dialog 位置及宽窄切换验证。其他原生/既有弹窗未由本分工重新实现。

## 本轮两项测试环境修正

- `PendingVideoStoreTest` 的首个失败来自未加载 Android 资源的 JVM 环境缺少 FileProvider 元数据。在此单测中仅替换 URI 生成边界，Room、注入的首次写入失败、实际恢复清单、重开和源文件字节断言继续真实执行。
- 标注集成测试的新增 EXIF 断言遇到 Robolectric Linux 未实现 `Os.dup`。测试将 URI EXIF 写入边界映射到该测试 Provider 的同一实际文件，继续调用真实文件 EXIF 写入，并从最终 JPEG 检查海拔与冻结时区；其余 ViewModel 解码/变换/失败保稿/保存/重开断言未削弱。Android 真机的文件描述符路径仍待设备验证。

以上测试修正尚未复跑；生产实现没有因模拟环境的限制添加兼容分支。
